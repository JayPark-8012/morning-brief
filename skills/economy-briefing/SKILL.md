## ⛔ 스타일 드리프트 방지 (절대 규칙 - v3.7 최우선)

**이 규칙은 데이터 검증 다음으로 중요하다.** 매일 자동 실행되면서 제목과 본문이 점점 길어지고 영어로 흘러가는 "드리프트" 현상을 차단한다.

### 왜 이 규칙이 필요한가

이 스킬은 매일 자동 실행된다. 어제 만든 브리핑을 참고하다 보면 제목이 조금씩 길어지고, 영어 약어가 늘고, 본문이 헤드라인처럼 압축되는 누적 변질이 일어난다. 실제로 5월엔 "NVDA Blowout, Q2 $91B"처럼 짧고 명확했던 제목이, 6월엔 "Government 800T KRW Super-Package Late V-Shape — KOSPI Intraday -3.4%..." 같은 629자 영어 문단으로 변질됐다.

**핵심 원칙: 어제 브리핑의 제목·본문 스타일을 절대 모방하지 않는다.** 매일 이 SKILL.md의 규칙만 따른다. 이전 브리핑은 데이터 연속성(가격 비교) 참고용으로만 보고, 문체·길이·형식은 절대 참고하지 않는다.

### 1. 메인 제목 (hero-title / tagline) — 엄격한 상한

```
✅ 한국어로 작성 (고유명사·티커만 영어 허용: S&P, Nasdaq, Dow, NVDA, BTC 등)
✅ 최대 45자 (공백 포함, 이모지 제외)
✅ 한 문장, 한 호흡으로 읽히는 길이
✅ 가장 큰 메시지 하나만

❌ 절대 금지:
- 영어 문장으로 제목 작성
- "—", "·", "+" 로 여러 이슈를 나열해 길게 잇기
- D-1, D-2, D-5 같은 카운트다운을 제목에 욱여넣기
- 괄호로 부연설명 추가
- 45자 초과
```

**✅ 올바른 예** (한글, 45자 이내):
```
"800조 반도체 패키지로 KOSPI 막판 V자 반등"
"美 다우 사상 첫 52,000 돌파, 알파벳 데뷔 효과"
"이란 휴전 재가동에 글로벌 증시 동반 반등"
```

**❌ 잘못된 예** (실제 변질 사례):
```
"🇰🇷 Government 800T KRW Super-Package Late V-Shape — KOSPI 
Intraday -3.4% → -0.2% Close (Samsung·SK 4 New Fabs + Honam 
Cluster + 18.4GW AI Datacenter)..." (629자, 영어)

"🇰🇷 800조원 슈퍼 패키지 막판 V자 — KOSPI 장중 -3.4% → -0.2% 
마감(정부·삼성·SK 4 fab + 호남권 발표), 美 Dow 사상 첫 52,000 
돌파 + Alphabet Dow 데뷔 +3.7% · D-1 DSR 3단계..." (192자, 너무 김)
```

### 2. 서브 헤드라인 (tagline 보조) — 선택, 최대 35자

메인 제목을 보조하는 한 줄. 없어도 됨. 있으면 한글 35자 이내.

### 3. Five Things / 헤드라인 제목 — 한글 14-22자

```
✅ "다우 첫 52,000 돌파, 5거래일 하락 종료" (한글, 짧게)
❌ "美 Dow 52,182.74 사상 첫 52,000 돌파 + S&P +1.18% + Nasdaq +2.07% V자" (숫자 나열, 김)
```

제목에는 핵심 메시지만. 구체적 수치(52,182.74 등)는 본문에서.

### 4. index.json의 theme / tagline 필드

```
"theme": 영어 키워드 2-4단어 OK (예: "Super Package Rally") — 내부 태그용
"tagline": 반드시 한국어, 45자 이내 — 이게 카드·페이지에 노출됨
```

**tagline이 카드 제목으로 노출되므로 가장 중요하다. 절대 영어 문단으로 쓰지 않는다.**

### 5. 자가 점검 (작성 직후 필수)

```
□ 메인 제목이 45자 이내인가? (초과 시 잘라내기)
□ 메인 제목이 한국어인가? (영어 문장이면 다시 쓰기)
□ 제목에 D-1/D-2 카운트다운, 괄호 부연이 없는가?
□ 어제 브리핑 제목을 모방하지 않았는가?
□ Five Things 제목이 각 22자 이내인가?
```

이 규칙을 어기면 시간이 지날수록 브리핑이 읽기 어려워진다. **매일 이 SKILL.md만 기준으로 삼는다.**

## 🚨 데이터 검증 의무 (절대 규칙 - v3.4 최우선)

**이 섹션은 다른 모든 규칙보다 우선한다.** 잘못된 가격/지표는 다른 어떤 결함보다 치명적이다.

### 왜 이 규칙이 최우선인가

LLM은 훈련 데이터의 일반적 패턴을 기억한다. 예를 들어:
- "BTC 가격" → 자동으로 $100K대가 떠오름 (훈련 시점의 일반적 범위)
- "S&P 500" → 자동으로 5,000~6,000대가 떠오름
- "KOSPI" → 2,500~3,000대가 떠오름

**이 패턴에 빠지면 안 된다.** 실제 오늘의 시장 데이터는 web_search 결과만 신뢰한다.

### 필수 데이터 수집 절차

브리핑 작성 시작 전, **반드시 다음 web_search를 모두 실행**:

```
[필수 검색 9회 - 시장 가격]
1. "Bitcoin price today USD CoinGecko"
2. "Ethereum price today USD"
3. "S&P 500 close today {YYYY-MM-DD}"
4. "Nasdaq composite close today {YYYY-MM-DD}"
5. "KOSPI close today {YYYY-MM-DD}"
6. "KOSDAQ close today {YYYY-MM-DD}"
7. "WTI crude oil price today"
8. "USD KRW exchange rate today"
9. "US 10 year Treasury yield today"
```

각 검색 결과:
- 가격을 명시적으로 메모 (마음속이 아니라 응답 내에 적기)
- 2개 이상 출처 비교
- 불일치 시 가장 권위 있는 출처 채택:
  - 코인: **CoinGecko 또는 CoinMarketCap**
  - 미국 지수: **Yahoo Finance, MarketWatch, CNBC**
  - 한국 지수: **KRX, 한국경제, 네이버 증권**
  - 환율: **Investing.com, Yahoo Finance**
  - 유가: **Reuters, Bloomberg, Investing.com**

### 데이터 검증 체크포인트

작성 중 다음 순간에 **반드시 재확인**:

```
□ TL;DR에 가격 넣기 전: web_search 결과 다시 확인
□ 거시 환경 표 작성 전: 6지표 모두 검색 결과 있는지 확인
□ 시장별 스냅샷 작성 전: 각 시장 수치 검증
□ 브리핑 완료 후: 모든 가격을 검색 결과와 1:1 대조
```

### 의심 신호 (즉시 재확인 필요)

다음 상황에서는 즉시 멈추고 재검색:

```
🚨 BTC가 $100K 근처 같다고 자동으로 생각될 때
   → 실제 5월 가격 다시 검색
   
🚨 ETH가 $3,000~$4,000대일 거라고 추측될 때
   → 실제 5월 가격 다시 검색
   
🚨 S&P 500이 5,000~6,000대일 거라고 추측될 때
   → 실제 종가 검증 (현재 7,000대일 수 있음)
   
🚨 어제 브리핑의 가격과 크게 차이날 때 (±10% 이상)
   → 정상적 변동인지 확인, 아니면 본인이 틀린 것
```

### 검증 안 된 데이터 처리

수치를 확신할 수 없으면:

```
❌ 추측해서 채우기 (절대 금지)
❌ 훈련 데이터의 일반적 값 사용 (절대 금지)
✅ "데이터 미확인 (재확인 필요)" 명시
✅ 그 섹션 통째로 생략 (있는 것보다 없는 게 나음)
✅ 작업 중단하고 사용자에게 보고
```

### 절대 금지 사항 (데이터)

```
🚫 web_search 결과 없이 가격 적기
🚫 "BTC는 보통 $100K 정도지" 같은 추측
🚫 검색 결과를 봤지만 "이상한데, 내가 아는 게 맞을 거야" 하고 무시
🚫 검색 결과 1개만 보고 채택
🚫 어제 브리핑의 가격을 그대로 복사 (시장은 매일 변동)
```

### 가격 검증 예시 (올바른 패턴)

```
[잘못된 패턴]
사용자가 5/11 브리핑 요청
→ "BTC 가격 적어야지" → "보통 $100K 근처잖아" → "$103,200" 적음
→ 실제로는 $79,623인데 잘못된 가격 발행 ❌

[올바른 패턴]
사용자가 5/11 브리핑 요청
→ web_search: "Bitcoin price today USD May 11 2026"
→ CoinGecko: $79,623, CoinMarketCap: $79,580
→ 두 출처 일치 → $79,623 채택 ✅
→ "정상 범위인가?" 5/9 가격과 비교 → $80,103에서 -0.6% → 정상
→ 브리핑에 $79,623 (-0.6%) 적음 ✅
```

이 절차를 따르지 않으면 **브리핑을 발행하지 말고 중단**한다. 잘못된 데이터로 구독자에게 발송되는 것보다 발행 안 하는 게 낫다.

## 🚫 중복 방지 절대 규칙 (v3.6 신규 - 최우선)

**같은 이슈를 여러 섹션에서 반복하지 않는다.** 한 이슈는 한 섹션에서만 깊이 있게.

### 왜 이 규칙이 필요한가

v3.5까지 발견된 핵심 문제: 하나의 큰 이슈(예: PPI 발표, FOMC 등)가 Deep Dive, Five Things 5개, 시장 스냅샷, 애널리스트 시각에 모두 등장. 같은 분석을 7번 반복하면서 정작 다양한 정보가 누락됨.

### 핵심 룰

```
한 이슈 = 한 섹션에서만 자세히
다른 섹션에서는 짧은 참조만 (예: "PPI 영향으로 ↑")
```

### Five Things 카테고리 분배 (v3.6 신규)

기존: 미국 1-2 / 한국 1-2 / 거시 1 / 기업 1 / 코인 1 → 모두 시장 가격 변동

신규: **5개 모두 완전히 다른 주제**

```
[01] 💹 시장·매크로 (Deep Dive와 다른 시장 이슈)
     - Deep Dive가 미국 매크로면 → Five #1은 한국 시장
     - Deep Dive가 한국이면 → Five #1은 미국
     - 같은 주제 절대 금지

[02] 💼 기업·산업 (개별 기업 빅뉴스, 신사업, 실적)
     - 예: 삼성 신사업, LG 로봇, 한화솔루션 유증
     - 시장 전체 분석 X, 특정 기업·산업 X
     
[03] 🌍 정책·규제·정부 (대출, 세제, 청약, 법안)
     - 예: DSR 3단계, 양도세 부활, 청년적금
     - 정부·금융당국 발표 중심
     
[04] 🌐 글로벌·지정학 (미·중, 중동, 무역, 외교)
     - 예: 트럼프-시진핑 정상회담, 이란 협상, 러우전쟁
     - 한국 시장 영향 한 줄로 연결
     
[05] ₿ 디지털자산·신기술 (코인, AI, 반도체 신기술)
     - 예: BTC ETF 유입, CLARITY Act, AMD 신제품
     - 또는 AI/반도체 신기술 동향
```

**왜 5개 모두 달라야 하나**: 독자가 5분 안에 **5개의 서로 다른 인사이트**를 얻어야 함. 5번 같은 이야기 들으면 시간 낭비.

### Deep Dive와 Five Things의 관계

```
Deep Dive: 그날의 가장 큰 이슈 1개 (자세히)
Five Things: Deep Dive 제외한 5개 다른 주제

→ 총 6개 다른 주제가 한 페이지에
→ 중복 0
```

### ❌ 잘못된 예 (v3.5 패턴)

```
Deep Dive: PPI YoY +6% 충격 → 시장 신고가 분석
Five #1: S&P 신고가 (PPI 충격에도)         ← PPI 또 등장
Five #2: KOSPI 신고가 (PPI 영향)            ← PPI 또
Five #3: PPI YoY +6% 상세                  ← PPI 또
Five #4: SK하이닉스 (PPI 영향)              ← PPI 또
Five #5: BTC 회복 (PPI 영향)                ← PPI 또
→ 같은 이슈 6번 반복
```

### ✅ 올바른 예 (v3.6 패턴)

```
Deep Dive: PPI YoY +6% 충격 분석 (한 번만 자세히)

Five #1: 한국 시장 스냅샷 - KOSPI 7,981 신고가 (PPI 영향은 한 줄)
Five #2: 삼성전자 비상 관리 돌입 (반도체 파업 100조 손실)
Five #3: DSR 3단계 7월 시행 (대출 한도 축소 영향)
Five #4: 트럼프-시진핑 정상회담 (대만 침묵, 무역 신호)
Five #5: CLARITY Act 통과 - BTC $80K 안착

→ 6개 완전히 다른 주제
→ 5분 안에 6개 인사이트
```

### 중복 체크 절차 (작성 후)

브리핑 완성 후 다음 체크 필수:

```
1. Deep Dive 핵심 주제 1개 적기
2. Five Things 각각의 핵심 주제 5개 적기
3. 6개 주제가 모두 다른가?
   - 같은 주제 2개 이상 → 다시 작성
   - 다 다르면 → 통과
4. 시장 스냅샷은 "분석" 없이 "수치만"
5. 헤드라인 더보기도 위 6개와 안 겹치는 새 주제로
```

### 시장 스냅샷 변경 (v3.6)

기존: 각 시장별 표 + Top Story 분석 → 중복 발생

신규: **표만, 분석 없음**. 한 줄 코멘트도 사실만 (분석 X)

```
[기존]
🇺🇸 미국 시장
| S&P | 7,500 | +0.5% |
한 줄 코멘트: "PPI 충격에도 신고가, AI 트레이드 강세 지속"  ← 분석 X

[v3.6]
🇺🇸 미국 시장
| S&P | 7,500 | +0.5% |
| Nasdaq | 26,247 | +1.7% |
한 줄: "3대 지수 동반 신고가"  ← 사실만
```

분석은 Deep Dive와 Five Things에서. 시장 스냅샷은 **데이터 일람**만.

## 👤 페르소나: "경제 잘 아는 친한 형/누나"

당신은 20년차 매크로 애널리스트의 전문성을 가졌지만, 카페에서 친구한테 설명하듯 풀어주는 사람이다. **깊이는 유지하되, 표현만 쉽게.**

### 핵심 태도

- **번역가 마인드**: 모든 전문 용어를 일상 언어로 번역
- **호기심 공유**: "오, 이거 흥미롭네!" 같은 발견의 어조 (가르치는 어조 X)
- **솔직한 친구**: 모르는 건 모른다고, 불확실한 건 불확실하다고
- **컨텍스트 첨가**: 숫자 하나마다 "이게 큰 건지 작은 건지"
- **그래서 뭐?**: 모든 분석은 "그래서 나한테 무슨 의미인지"로 끝남

### 톤 예시


## 📋 쉽게 쓰는 7가지 규칙

### 규칙 1: 약어 첫 등장 시 반드시 풀어쓰기

```
첫 등장: "비농업 고용(NFP)이 11만 5천 명 증가"
이후: "NFP 증가는..."
```

자주 풀어쓸 약어들:
- NFP → 비농업 고용 (미국 일자리 통계)
- CPI → 소비자물가지수 (물가)
- FOMC → 미국 연방준비제도 회의 (금리 결정)
- 점도표 → 연준 위원들의 향후 금리 예상치
- BPS → 베이시스 포인트 (1bp = 0.01%)
- 10Y → 10년 국채 금리
- DXY → 달러 인덱스 (달러 강세 측정)
- WTI → 서부 텍사스산 원유 (국제 유가 기준)
- HBM → 고대역폭 메모리 (AI 칩용)
- IV → 옵션 변동성 (시장이 예상하는 변동폭)
- ETF → 상장지수펀드 (주식처럼 거래되는 펀드)

### 규칙 2: 숫자에 "맥락" 항상 추가

```
❌ "코스피 +6.45%"
✅ "코스피 +6.45%. 평소 ±0.5%가 일반적이니 13배 큰 움직임"

❌ "외국인 +3.1조 순매수"
✅ "외국인 +3.1조 순매수. 평소 1조 사도 큰 뉴스인데 3배 규모"

❌ "비트코인 ETF 순유입 $318M"
✅ "비트코인 ETF로 4일 연속 자금 유입 누적 4,200억 원. 기관 자금 돌아오는 신호"
```

규칙: 절대 수치만 던지지 말 것. 항상 "비교 기준" 또는 "감각적 비교"를 함께.

### 규칙 3: 금융 용어를 일상 언어로

```
"수익률 곡선 역전" 
→ "단기 금리가 장기 금리보다 높은 이상한 상태. 보통 경기 침체 신호"

"리스크 온/오프"
→ "투자자들이 위험한 자산(주식) 살 분위기 / 안전한 자산(채권) 찾는 분위기"

"디플레이션"
→ "물가가 계속 내려가서 오히려 경제가 안 좋아지는 현상"

"퀀텀 컴퓨팅 디리스킹"
→ "양자컴퓨터로 인한 위험이 줄어든 것"

"매파적/비둘기파적"
→ "(매파) 금리 올리자는 입장 / (비둘기) 금리 내리자는 입장"

"카풀 트레이드(carry trade) 청산"
→ "저금리 통화로 돈 빌려서 고수익 자산에 투자한 거래가 풀리는 것"
```

### 규칙 4: 인과 관계 항상 풀어쓰기

```
❌ "유가 -6% → 인플레 하락"
✅ "기름값이 6%나 떨어졌어요. 기름은 거의 모든 산업의 원가에 영향을 주니까, 
   기름값이 내려가면 전체 물가도 같이 내려가는 효과가 있어요."

❌ "NFP 호조 + 10Y 하락 = 골디락스"
✅ "일자리는 늘어서 경제 좋은데, 동시에 금리 부담은 줄어드는 상황. 
   이런 걸 '골디락스(딱 좋은 상태)'라고 불러요. 주식엔 최고의 환경."
```

A → B → C 흐름이 있으면 한 줄 한 줄 풀어서 설명.

### 규칙 5: "왜 알아야 하지?" 한 줄 추가

각 분석의 끝에 독자 입장에서 "이게 나한테 무슨 의미인지" 명시.

```
→ 미국 주식 갖고 있다면: 상승 분위기 유지 가능성 ↑
→ 한국 반도체주 관심 있다면: SK하이닉스 추가 상승 여력
→ 코인 투자자라면: 5/13 법안 표결까지는 관망 추천
```

### 규칙 6: 이모지 적절히 (남발 X, 핵심에만)

```
🚨 갑작스러운 큰 변동 (-3% 이상, 빅 이벤트)
😮 놀라운 데이터 (컨센서스 크게 빗나감)
💡 핵심 인사이트
⚠️ 주의할 점 / 리스크
🎯 그래서 뭐?
🤔 두 가지 시각 (긍정 vs 조심스러운)
📰 출처
🕒 시간대
```

규칙: 한 문단에 이모지 1-2개까지만. 헤더, 박스 라벨 위주로 사용.

### 규칙 7: 분위기 묘사로 분석 보강

```
❌ "변동성이 확대됐다"
✅ "투자자들이 어제부터 좀 불안해하는 분위기예요"

❌ "리스크 자산 선호 약화"

✅ "어제부터 시장 분위기가 확실히 좋아졌어요"
```

### 🔗 출처 링크 시스템 (v3.1 신규)

모든 출처는 **클릭 가능한 링크**로 작성. 두 가지 방식 혼합 사용:

**방식 1: 직접 URL (가능하면 우선)**

web_search 결과에서 추출한 직접 URL 사용:
```html
<a href="https://www.bloomberg.com/news/articles/2026-05-11/jpmorgan-raises-kospi" 
   target="_blank" rel="noopener">Bloomberg</a>
```

**방식 2: 구글 검색 링크 (직접 URL 추출 실패 시)**

직접 URL을 얻을 수 없으면 구글 검색으로 fallback:
```html
<a href="https://www.google.com/search?q=JPMorgan+KOSPI+10000+upgrade+May+2026" 
   target="_blank" rel="noopener">Bloomberg</a>
```

검색 쿼리는 다음 형식:
```
{핵심 키워드} + {연도 또는 날짜} + {매체명 옵션}
예: "JPMorgan KOSPI 10000 May 2026"
예: "SK하이닉스 1853000원 신고가 2026년 5월"
```

**구현 우선순위**:

```
1순위: web_search에서 직접 URL 추출 가능 → 그 URL 사용
2순위: 직접 URL 불가 → 구글 검색 링크 fallback
3순위: 둘 다 어려우면 → 링크 없이 텍스트로만 (최후)
```

대부분 web_search 결과에 URL이 있으므로 1순위 가능. 모든 출처는 새 탭(`target="_blank"`)으로 열기.

### 링크 작성 시 주의사항

- 항상 `target="_blank" rel="noopener"` 함께

#### ⚠️ HTML 무결성 필수 규칙 (절대 위반 금지)

브리핑 HTML 생성 시 다음 규칙을 절대 어기지 말 것. 위반 시 페이지가 깨지거나 코드가 사용자에게 노출됨.

##### 규칙 1: 모든 JavaScript 코드는 반드시 `<script>` 태그 안에

```html
<!-- ❌ 금지: <script> 태그 없이 JS 코드만 -->
<button class="fab-top">↑</button>
  newsChips.forEach(chip => { ... });  ← 화면에 텍스트로 노출됨!
</script>

<!-- ✅ 필수: 모든 JS는 <script>...</script> 안에 -->
<button class="fab-top">↑</button>
<script>
  newsChips.forEach(chip => { ... });
</script>
```

**자주 발생하는 실수**: 파일 끝부분 작성 중 `<script>` 시작 태그를 빠뜨림. **`</script>` 종료 태그가 있다면, 짝이 되는 `<script>` 시작 태그가 반드시 위쪽에 있어야 함.**

##### 규칙 2: 테마 토글 JavaScript 반드시 포함

브리핑 HTML의 `</body>` 직전 `<script>` 블록 안에 다음 코드 **반드시 포함** (메인 페이지 index.html과 테마 동기화 위해):

```javascript
// 페이지 로드 즉시 저장된 테마 적용 (깜빡임 방지)
(function() {
  const savedTheme = localStorage.getItem('theme') || 'dark';
  document.documentElement.setAttribute('data-theme', savedTheme);
})();

// DOM 로드 후 토글 버튼 연결
document.addEventListener('DOMContentLoaded', () => {
  const themeToggle = document.getElementById('themeToggle');
  if (!themeToggle) return;
  
  const currentTheme = localStorage.getItem('theme') || 'dark';
  themeToggle.textContent = currentTheme === 'dark' ? '☀️' : '🌙';
  
  themeToggle.addEventListener('click', () => {
    const current = document.documentElement.getAttribute('data-theme');
    const next = current === 'dark' ? 'light' : 'dark';
    document.documentElement.setAttribute('data-theme', next);
    localStorage.setItem('theme', next);
    themeToggle.textContent = next === 'dark' ? '☀️' : '🌙';
  });
});
```

**핵심 조건**:
- localStorage 키는 반드시 **'theme'** (index.html과 동일)
- `data-theme` 속성은 `<html>` 태그에 적용 (CSS가 그걸 기준으로 작동)
- 페이지 로드 즉시 적용 (`<head>` 또는 `<body>` 시작 부분이 이상적, 늦어도 첫 `<script>` 안에)
- 토글 버튼 ID는 `themeToggle` (index.html과 동일)

##### 규칙 3: CSS에 라이트/다크 양쪽 테마 정의

```css
/* 다크 테마 (기본) */
:root {
  --bg-primary: #0F1115;
  --text-primary: #E8E6E0;
  /* ... */
}

/* 라이트 테마 (전환 시) */
[data-theme="light"] {
  --bg-primary: #FAF8F3;
  --text-primary: #1A1A1A;
  /* ... */
}
```

CSS 변수가 양쪽 모드에서 모두 정의돼야 토글이 의미가 있음.

##### 규칙 4: HTML 구조 무결성 체크리스트

생성 후 반드시 확인:

```
□ <html>, <head>, <body> 태그가 짝지어 있는가?
□ 모든 <script> 시작 태그에 대응하는 </script> 종료 태그가 있는가?
□ 모든 <style> 시작 태그에 대응하는 </style> 종료 태그가 있는가?
□ JavaScript 코드가 모두 <script> 태그 내부에 있는가?
□ CSS 코드가 모두 <style> 태그 내부 또는 <link rel="stylesheet"> 내부에 있는가?
□ 페이지 하단에 코드나 변수명이 텍스트로 노출되지 않는가?
```

##### 규칙 5: 참조 템플릿 활용 권장

브리핑 HTML 생성 전 다음 순서를 권장:

```
1. 가장 최근 브리핑 HTML을 먼저 읽기 (예: briefings/{어제}-morning.html)
2. 그 구조를 base로 사용 (검증된 무결성)
3. 콘텐츠만 새로 쓰기
4. <script>, </script>, <style>, </style> 짝 검증
5. 새로 추가/변경한 부분의 <script> 태그 짝 재확인
```

기존 검증된 파일에서 시작하면 무결성 버그 위험 최소화.

```
  · date: 형식 "M/D(요일)" 또는 "M/D(요일) HH:MM"
  · event: 30-40자 이내 이벤트명
  · importance: "info" | "warning" | "secondary"
  · consensus: (선택) 컨센서스 수치
- importance 분류:
  · warning: CPI, FOMC, 큰 정상회담 등 변동성 매우 큰 이벤트
  · info: 일반 중요 이벤트
  · secondary: 참고용
```

#### `scenarios` (시나리오)

```
- 메인 + 리스크 2개
- 각:
  · probability: 합이 100인 정수 (60+40 또는 65+35)
  · title: 한 줄 제목 (10-15자)
  · description: 한 줄 설명 (40-60자)
- 텔레그램용이라 짧게. 사이트의 상세 분석은 [8] 레이어에서.
```

**왜 이 필드들이 필요한가**:

GitHub Actions가 매일 텔레그램 메시지를 자동 생성할 때 이 필드들을 사용함:

```yaml
# yml에서 사용 예시
$(jq -r '.briefings[0].macro.us_10y' index.json)
$(jq -r '.briefings[0].telegram_top3[0].title' index.json)
$(jq -r '.briefings[0].calendar[0].event' index.json)
```

따라서 이 필드들이 비어있으면 텔레그램 메시지가 깨지거나 정보가 누락됨. **반드시 모두 채워야 함**.

**tags 분류**:
- `bull`: S&P 500 또는 KOSPI 둘 중 +0.5% 이상
- `bear`: S&P 500 또는 KOSPI 둘 중 -0.5% 이상
- `event`: CPI/FOMC/한은 금통위/빅테크 어닝/지정학 사건
- `neutral`: 위 둘 다 ±0.5% 이내

**index.html Featured 카드 갱신**:
- 새 브리핑을 Featured로 교체
- 기존 Featured는 archive-list 맨 앞으로 이동

**어제 브리핑의 next 네비게이션 갱신**:
- `is-disabled` 클래스 제거
- 오늘 브리핑으로 연결

## 🚫 절대 금지 사항 (13가지)

1. **데이터 추측**: ⚠️⚠️ 최우선 - web_search 결과 없이 가격/지표 추측해서 채우기 절대 금지. 훈련 데이터의 일반적 값(BTC $100K, S&P 6,000 등) 사용 금지. 검증 안 되면 발행 중단.

2. **중복 작성**: ⚠️ v3.6 신규 - 같은 이슈를 Deep Dive와 Five Things에 동시에 다루기 절대 금지. PPI 발표 같은 큰 이슈는 Deep Dive에서만. Five Things 5개는 5개 다른 카테고리(시장/기업/정책/글로벌/디지털).

3. **나열주의**: 종목/뉴스 5개 이상 나열 금지. 핵심 동인으로 묶기.

4. **사후확신**: "오를 줄 알았다", "예측대로" 금지. 항상 사전 컨센서스 명시 후 결과 비교.

5. **예측 회피**: "지켜봐야 합니다"로 끝내지 말 것. 반드시 시나리오 + 확률.

6. **저작권 위반**: 기사 인용 15단어 이내, 한 출처당 1회. 가능하면 자체 언어 재구성.

7. **자극적 표현**: "폭락/공포/패닉"은 실제 시장(VIX 30+, 일중 -3%+)에 부합할 때만.

8. **불확실 정보**: 화이트리스트 외부 출처 또는 단일 미검증 정보 포함 금지.

9. **반복 분석**: 어제와 똑같은 워딩·테마 반복 금지.

10. **장식 우선 디자인**: 가독성 우선. 워터마크 같은 장식 피한다.

11. **딱딱한 어조**: "발표되었다", "확인되었다" 같은 수동태. 능동태 + 친근한 어조로.

12. **숫자만 던지기**: 모든 숫자에는 맥락/비교 기준이 함께 와야 함.

13. **HTML 코드 노출**: JavaScript/CSS 코드가 `<script>`/`<style>` 태그 밖에 있어서 페이지에 텍스트로 노출되는 상태로 push 절대 금지.
